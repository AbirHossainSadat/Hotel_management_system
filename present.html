Algorithm 1: Concept & Theory

Dijkstra's Shortest Path Algorithm

Purpose: Implemented in the Guest Dashboard to dynamically calculate the most efficient route and distance from the hotel to various local attractions, transport hubs, and facilities.

  • Graph Representation: We map physical locations as Vertices and the roads connecting them as Edges with specific weight values (Distance in KM).
  • Greedy Approach: The algorithm iteratively selects the unvisited node with the lowest cumulative distance.
  • Dynamic Recalculation: Unlike static maps, if a pathway is removed or added to the database, the PHP logic instantly adapts to find the new optimal route.
// Theoretical Complexity
Time Complexity: O(V^2) or O(E + V log V)
Space Complexity: O(V)
Where V = Locations, E = Routes

Algorithm 1: PHP Implementation

Dijkstra's Logic Breakdown

Below is the actual implementation utilizing PHP's native SplPriorityQueue to act as our Min-Heap, drastically improving the speed of node extraction compared to standard array sorting.

hotel_routing.php PHP 8.x
function calculateShortestPath($graph, $startNode, $targetNode) { $distances = []; // Stores min distance to each node $previous = []; // Tracks path history for reconstruction $pq = new SplPriorityQueue(); // Native Min-Heap // 1. Initialization phase foreach ($graph as $node => $adjacencies) { $distances[$node] = INF; // Set initial distances to infinity $previous[$node] = null; } $distances[$startNode] = 0; $pq->insert($startNode, 0); // 2. Processing nodes while (!$pq->isEmpty()) { $currentNode = $pq->extract(); if ($currentNode === $targetNode) break; // Early exit optimization foreach ($graph[$currentNode] as $neighbor => $cost) { $altDistance = $distances[$currentNode] + $cost; // Edge Relaxation: If new path is cheaper, update it if ($altDistance < $distances[$neighbor]) { $distances[$neighbor] = $altDistance; $previous[$neighbor] = $currentNode; // Negative distance used because SplPriorityQueue is a Max-Heap by default $pq->insert($neighbor, -$altDistance); } } } return ['distance' => $distances[$targetNode], 'path' => $previous]; }

Algorithm 2: Concept & Theory

Levenshtein Edit Distance

Purpose: Powering the fuzzy-search feature. When a guest misspells a location or an amenity (e.g., typing "Airprt" instead of "Airport"), the system must still return the correct result rather than a blank page.

  • Metric Definition: It calculates the minimum number of single-character edits required to change one word into another.
  • Allowed Operations:
    1. Insertion (Airprt ➔ Airport)
    2. Deletion (Beeach ➔ Beach)
    3. Substitution (Rooom ➔ Room)
  • Application: We compare the user's input against the entire database vocabulary, scoring each match. The lowest scores (fewest edits) are suggested to the user.
// Theoretical Complexity
Time Complexity: O(M * N) // Length of word 1 * word 2
Space Complexity: O(M * N) // Dynamic Programming Matrix

Why not SOUNDEX?
While PHP offers soundex() for phonetic matching, Levenshtein is strictly character-based, making it far more reliable for international hotel locations and non-English location names which may not follow English phonetic rules.

Algorithm 2: PHP Implementation

Fuzzy Search Integration

Here we leverage PHP's highly-optimized internal levenshtein() function (written in C) rather than writing our own matrix algorithm, ensuring ultra-fast database filtering.

search_suggestions.php PHP 8.x
function getSearchSuggestions($userInput, $databaseRecords) { $userInput = strtolower(trim($userInput)); $closestMatches = []; $shortestDistance = -1; foreach ($databaseRecords as $record) { $targetWord = strtolower($record['location_name']); // Calculate Levenshtein Distance $distance = levenshtein($userInput, $targetWord); // Exact Match Found - Terminate search immediately if ($distance === 0) { return [$record['location_name']]; } // Heuristic: Bonus if the input is a direct substring if (strpos($targetWord, $userInput) !== false) { $distance -= 2; // Synthetically lower the score } // Track the best results (Lowest distance score is better) if ($distance <= $shortestDistance || $shortestDistance < 0) { $shortestDistance = $distance; $closestMatches[] = [ 'name' => $record['location_name'], 'score' => $distance ]; } } // Sort array by score ascending (0 is perfect, 1 is 1 edit, etc.) usort($closestMatches, fn($a, $b) => $a['score'] <=> $b['score']); return array_slice($closestMatches, 0, 3); // Return Top 3 }

Algorithm 3: Concept & Theory

Multi-Criteria Linear Search

Purpose: Used in the Staff Operations Dashboard. It allows receptionists to look up guest folios using incomplete or fragmented data across multiple fields (e.g., knowing only a phone number snippet and a partial first name).

  • Algorithm Nature: A sequential evaluation algorithm. It inspects every element in a dataset one by one until a match is found.
  • Multi-Parameter Logic: Implements logical OR/AND gates dynamically based on what the staff member inputs.
  • Fallback Mechanism: Executed post-database query when filtering complex, multi-joined arrays in memory is faster than running multiple heavy SQL LIKE '%...%' operations.
// Theoretical Complexity
Time Complexity: O(N) // N = Total Guest Records
Space Complexity: O(K) // K = Matches stored in array

Use Case Scenario:
Staff searches for Name: "Joh" and Phone: "555". The algorithm scans the array. Record 1 (John, 555-0101) evaluates TRUE. Record 2 (Jane, 555-9999) evaluates FALSE (Name mismatch).

Algorithm 3: PHP Implementation

Sequential Logic Implementation

This snippet demonstrates how boolean flags and string-position functions (stripos) are combined to evaluate multi-field arrays seamlessly without throwing undefined index errors.

staff_lookup.php PHP 8.x
function filterGuestRecords($allGuests, $searchParams) { $filteredResults = []; // O(n) Linear iteration through the payload foreach ($allGuests as $guest) { $isMatch = false; // Safely extract parameters using null coalescing operator $qName = $searchParams['name'] ?? ''; $qEmail = $searchParams['email'] ?? ''; $qPhone = $searchParams['phone'] ?? ''; // Condition 1: Check Name (Case Insensitive Substring) if (!empty($qName) && stripos($guest['name'], $qName) !== false) { $isMatch = true; } // Condition 2: Check Email if (!empty($qEmail) && stripos($guest['email'], $qEmail) !== false) { $isMatch = true; } // Condition 3: Check Phone if (!empty($qPhone) && strpos($guest['phone'], $qPhone) !== false) { $isMatch = true; } // If any condition flipped the flag to true, store it if ($isMatch) { $filteredResults[] = $guest; } } return $filteredResults; }

System Integration

Architectural Synthesis

These three algorithms work in tandem to create a cohesive, intelligent hotel management environment:

  • Dijkstra's Algorithm transforms static maps into dynamic, living networks, optimizing guest travel times.
  • Levenshtein Distance provides a forgiving UX, drastically reducing "0 Results Found" errors and guest frustration.
  • Linear Searching provides robust, un-breakable administrative filtering without constantly hitting the SQL database with expensive queries.
